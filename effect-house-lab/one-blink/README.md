# ONE BLINK · 기억한 별 찾기

상태: 브라우저 플레이 검토본 준비 / 네이티브 조립 대기. 2026-09-06.

## 실행

이 폴더에서 `node server.cjs`를 실행하고 http://127.0.0.1:4173/ 을 연다. 현재 작업 중 서버가 이미 실행되어 있다. 웹 배포나 구독 서비스가 아니라 게임의 규칙·화면을 확인하는 로컬 도구다. 브라우저 검토본은 별도 패키지 없이 실행된다.

카메라와 소리는 선택 사항이며 처음에는 꺼져 있다. 카메라는 버튼을 눌러 허용한 경우에만 표시하며 영상 저장·전송 코드는 없다.

## 검증 결과

| 범위 | 결과 |
|---|---|
| 1,000개 시드 × 3라운드 | 라운드별 6/9/12개 카드, 정답 정확히 1개 |
| 시간 계산 | 기억·정답 연출 제외, 오답 1초 가산 포함 |
| 종료·중복 입력 | 시간 초과 이후 정답 구제 불가, 같은 오답 중복 처리 방지 |
| 재시작·잘못된 입력 | 상태 초기화, 잘못된 입력 무시 |
| 브라우저 실제 조작 | 3라운드 성공, 오답 +1초, 시간 초과, 재시작 확인 |
| 화면 | 데스크톱 1280×720 및 모바일 360×640 검토, 가로 넘침 없음 |
| 브라우저 오류 | 검토 시 콘솔 오류 없음 |
| 네이티브 타입 | 설치된 Effect House 5.14 API 정의로 TypeScript 검사 통과 |

자동 조작으로 나온 짧은 성공 기록은 사람의 난이도 테스트 결과가 아니며 홍보 수치로 쓰지 않는다. 실제 엔진 컴파일·휴대폰 실행은 아직 검증하지 못했다.

검사: `node --test core.test.cjs`. 네이티브 재생성: `node build-native.cjs` 후 `node_modules/.bin/tsc.cmd -p native/tsconfig.json`. 후자는 이 PC에 설치된 Effect House SDK 경로를 사용하며 다른 PC에서는 빌드 스크립트로 경로를 재생성해야 한다. 타입 검사를 위해 TypeScript 개발 의존성이 필요하다.

## 파일 구성

- `core.js`: 브라우저와 네이티브 소스에서 공유하는 게임 규칙.
- `app.js`, `index.html`, `style.css`: 브라우저 화면·조작·선택적 소리와 카메라.
- `assets/`: 직접 코드로 그린 별 12종 SVG/PNG 및 패널·버튼·아이콘.
- `build-assets.cjs`: sharp로 에셋 재생성. 이 PC의 번들 node_modules를 NODE_PATH로 지정한다.
- `native-controller.fragment.ts`: Effect House 입력·화면·녹화 시작 이벤트 연결 코드.
- `build-native.cjs`: 공유 규칙과 네이티브 어댑터를 합쳐 TypeScript 및 조립 명세 생성.
- `native/scene-spec.json`: 위치·계층·텍스처·필드 연결 명세. 자동 가져오기 파일이 아니다.

## 네이티브 작업 재개

Effect House 5.14.0.1999 설치 및 파일 무결성 8,036/8,036 통과. 앱은 창이 나타나기 전에 `0xC0000409`로 종료된다. 실행 로그의 `WindowsScreen.cpp: create DC failed`를 확인했지만 원인은 확정하지 않았다. 보안 설정·그래픽 드라이버는 변경하지 않았다.

앱이 정상 실행되면 기본 카메라 씬에 명세대로 오브젝트를 조립한다. 공식 스크립트 생성 경로로 OneBlinkController를 등록하고 엔진 컴파일 결과를 확인한다. 컴포넌트를 붙인 다음 실제 반환된 오브젝트/텍스처 참조를 연결한다. 임의 GUID나 조작한 .ehproj는 사용하지 않는다.

이어서 한글 폰트·줄바꿈, 이미지 터치 범위, 프레임 시간, 3라운드 재시작, 녹화 시작 초기화, 휴대폰 카메라 구도를 확인한다. 네이티브 결과 아트·사운드는 검토본과 아직 동등하지 않다. 최종 사용자 확인 전에는 게시하지 않는다.
